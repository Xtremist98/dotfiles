## Current project (2026-08-20) — IDM-style download manager for Linux
- **Goal:** an IDM (Internet Download Manager) clone on Linux: Python + GTK4/libadwaita, OWN multi-threaded segmented engine (no aria2), full video grabber (yt-dlp fallback for HLS/DASH + direct-media detection), browser extension (Firefox+Chrome MV3) that catches download links/video and hands them to the app over a local HTTP IPC server. User chose: own engine mirroring IDM, GTK4 stack, full video grabber scope.
- **Location:** source of truth `~/.local/share/idm-linux/` (mirrors NordVPN-GUI layout). Modules: `engine.py` (segmented engine), `manager.py` (queue/settings/persistence), `gui.py` (Adw app + dialogs + rows), `tray.py` (SNI), `server.py` (HTTP IPC on 127.0.0.1:43610), `video.py` (grabber), `cli.py` (headless + entry). Launcher `~/.local/bin/idm` (`python3 cli.py "$@"`); desktop `~/.local/share/applications/idm.desktop`. Config `~/.config/idm/settings.json` (default_dir, num_segments, speed_limit B/s, max_concurrent); state `~/.local/state/idm/queue.json` + per-download `.name.idmparts/` dirs in the dest folder (`0.part`…`N.part` + `meta.json`).
- **Engine (engine.py, VERIFIED headlessly):** probe = HEAD (fallback GET Range:0-0) → size/accept-ranges/filename(Content-Disposition)/etag. Segmented: splits into N ranges; one `_SegmentWorker` thread per segment appends to its `.part` file, resume = stat part size → Range from there; retries with backoff (max 5); pause via Event (workers sleep on `_pause_wait`, part files persist); cancel deletes parts; merge = concatenate parts → fsync → rmdir. 8-segment 100MB test completed byte-exact (104857600); crash-kill resume restarted at exactly the part bytes (5.0%) and merged clean; 1MB/s throttle holds within ~30% (token bucket, acceptable). CRITICAL gotcha already hit: `_SegmentWorker` originally named its range attrs `self.start/self.end` which SHADOWED `threading.Thread.start()` → `w.start()` would crash; renamed to `seg_start/seg_end`. Also: server ignoring Range on resume (HTTP 200 with pos>0) → raise and retry; single-segment fallback when total unknown or `accepts_ranges` false.
- **Manager:** max_concurrent slots (default 3), queued tasks auto-start on slot free; `restore()` reloads queue.json + walks default_dir for `.idmparts` dirs → resumes unfinished; etag/total mismatch wipes parts and restarts. VERIFIED: new manager after "crash" resumed the 100Mb task from part files.
- **GUI (gui.py, IDM-style redesign 2026-08-20):** Adw.Application `org.linuxer.idm` (single-instance). MainWindow = category sidebar (All/Downloading/Paused/Completed/Failed with live counts) + Gtk.ColumnView table with columns Filename (name+url+ProgressBar+% stacked), Size, **Connections (live N/N active segments)**, Speed, ETA, Status — plus header (New, Video grab, Paste, Resume, Pause, Cancel, Remove, Options), bottom status bar (downloaded/active/total speed), right-click context menu, empty StatusPage. Add dialog is IDM-style: URL + Save-as + folder picker + **Connections spin + per-download speed limit + "Start Download" vs "Download Later"** (Later = queued). Video grab dialog: enter page URL → Detect (video.detect_media) → format list → Download (direct→engine, else yt-dlp best). Options dialog: General (default folder, **close-to-tray, completion notifications**), Downloads (default connections, simultaneous, resume-on-launch), Speed (global KB/s), Network (User-Agent).
- **SMALL DOWNLOAD PANEL (IDM behavior, NEW):** when a download starts, a compact borderless always-on-top `DownloadPanel` (~380×96, `window.download-panel` CSS) appears stacked bottom-right (above the bar) showing filename, progressbar, size/speed/ETA/connections and open-app/pause/cancel buttons — the FULL APP WINDOW DOES NOT OPEN for downloads.
